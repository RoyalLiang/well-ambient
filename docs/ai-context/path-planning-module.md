# 路径规划模块 AI 上下文

来源：项目根目录 `全局领航能力汇总.xlsx`，第一个 sheet `功能列表`。

用途：供 AI 需求解构、工时估算、风险识别和配置判断使用。该文档只描述路径规划模块，不代表 well-ambient 协同平台本身的全部能力。

## 模块边界

路径规划模块面向自动驾驶/无人车/港口堆场等现场的领航路径生成、短路径推荐、道路/区域约束、交通权重、特殊作业场景和现场定制能力。AI 在解析需求时应先判断需求是否属于路径规划模块；若需求属于系统协同平台、Jira/GitLab 集成、看板或报表，不应套用本模块能力清单。

## 已耐久标准能力

- 接受任务目的点位计算领航长路径：不可配置；验证重点为起终点吸附，优先直线，其次弯道。
- 在领航过程中给出推荐短路径可行区域：不可配置。
- 规避死锁：不可配置。
- 道路权重偏好：可配置；验证点包括负系数。
- vpb 选择：可配置。
- 取消领航：不可配置。
- 优先级行驶路权：可配置。
- 删除幽灵车：不可配置。
- 禁行区：可配置。
- 禁停区：可配置。
- 流量控制区域：可配置。
- 拖挂模型适配：不可配置。

## AI 使用规则

- 先判断需求是否属于路径规划模块，再引用本清单。
- 对“已耐久”能力，优先估算配置、现场适配、回归验证和联调成本，不按从零开发估算。
- 对“已初步验证/已开发完成”能力，重点识别现场适配、反馈闭环、测试覆盖和回归风险。
- 对“开发中/待开发/进阶探索”能力，应估算设计、实现、仿真/现场验证、配置项治理、回滚方案和多现场差异。
- 对可配置能力，需求解构时必须输出配置项、默认值/取值范围、作用域（全局/项目/现场/堆场/道路/区域/车辆级）和验证场景。
- 对不可配置能力，若用户要求“通过配置实现”，AI 应提示可能需要代码改造或能力扩展。
- 若需求提到具体现场，应结合 `应用现场项目` 判断是否已有类似落地经验；已有现场经验可降低不确定性，但不能省略现场验证。
- 若功能状态为空或配置属性未明确，应在 `missing_info` 和 `meeting_questions` 中要求确认。

## 推荐 Prompt 摘要

路径规划模块已有 39 项能力：13 个标准功能、23 个扩展能力、2 个进阶探索、1 个定制化功能。其中 20 项已耐久、7 项已初步验证、3 项已开发完成、3 项开发中、5 项待开发。25 项可配置、12 项不可配置、2 项配置属性未明确。AI 在解构路径规划需求时，应优先判断需求落入已耐久、已验证、开发中还是待开发能力；已耐久能力按配置/现场适配/回归估算，不按从零开发估算；可配置能力必须输出配置项与验证场景；不可配置能力若被要求配置化，应提示需要代码改造或能力扩展。
