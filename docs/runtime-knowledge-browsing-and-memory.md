# 浏览知识与复用背景

在 AI 治理 → Skill 中心点击“知识快照内容”，可按关键词、来源类型、项目或仓库标识浏览已整理证据。展开来源时重新核验原记录；撤回、归档或变更的来源正文不再展示。分页固定到同一快照和已应用筛选，快照过期须重新查询。该管理视图要求全局超级管理员和 `ai_context:read`，不改变外部 MCP 的发布范围。

MCP 已知项目或仓库时可直接调用 `well_ambient_knowledge_get_context`，无需每次先 describe。推荐从小预算开始：

```json
{"text":"评估车辆资源锁的能力边界","projects":["NS2"],"token_budget":1200,"format":"dense"}
```

`dense` 使用固定列序 `[ref,scope,claim,title,content]`，减少每个证据段重复的字段名。需要精确细节时只展开相关 `source_ref`。默认空格式保留原有布局，旧调用方可继续使用。

将返回的 `memory_hash` 与正文、证据引用及缺口保存在当前会话。再次请求背景时，只有仍持有原正文才传入 `known_memory_hash`。服务仍重新鉴权、检索和核验来源；如果内容、版本、时效及缺口都未变化，返回 `unchanged: true` 并省略重复正文。回执不能恢复已丢失内容，不跨身份或会话传播。服务不缓存背景正文，审计仍记录被核验的来源引用。

`token_count` 和 `token_budget` 继续采用 compact 字段 UTF-8 字节数的保守上界，不代表模型实际 Token 数，响应元数据不在 compact 预算内。`reused_bytes` 表示省略的正文规模。合成回归中，重复背景响应 JSON 为 2116 → 516 字节，约减少 75.6%；不能据此宣称真实业务 Token 成本或评审质量已经改善。

页面快照、需求记录、已发布方案和能力注册均不是生产实现或现场验收证明。结合源更新时间、整理时间、声明类型与缺口进行判断。
