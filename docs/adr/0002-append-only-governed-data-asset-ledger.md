# 使用追加式治理账本并分离热元数据与冷载荷

跨 Jira、本地排期、GitLab、评论、报告和模型分析的可追溯事实统一写入追加式数据资产账本，但领域当前状态仍由各自写模型拥有。账本把可索引的来源、主体、时间、分级和保留元数据与大体积原始载荷物理分离，并使用稳定高水位的 keyset cursor 查询；这样牺牲了直接更新历史记录和单表查询的便利，换取幂等重放、历史可复核、热查询不搬运大载荷以及未来按时间归档或分区的能力。

## Consequences

- 更正、删除声明和模型重算都追加新事件或新快照，不修改既有资产。
- 领域事件与其资产记录必须在同一数据库事务中提交；外部系统写入继续通过 outbox 解耦。
- 列表查询不提供无界 offset 或实时全量 count；调用方使用固定输入水位和不透明 cursor。
- SQLite 是当前已验证适配器；表结构保留时间与范围键，未来迁移到分区数据库时不改变模块接口。
