# Jira → Issue 每日同步预览

入口：配置中心 → Jira → Issue 同步。这是独立于“每日 Jira”的新配置。

选择已配置的 Jira 项目、GitLab 分组命名空间和一个分组内的 Issue 承载仓库，保存后生成预览。每天的执行时间使用北京时间，初始值为 09:00，默认不启用。开启“每日预览”后，服务进程每分钟检查到期时间，每天对当前配置版本生成一次预览；停机后恢复会补做当天已到期的预览，不补做更早日期。

预览从本系统已经同步的 Jira 资料生成，保留 Jira Key、来源状态、更新时间、草稿正文和稳定的去重标识。最多展示前 100 条，明确标出匹配总数与截断；保留最近 30 份结果，调度幂等标识独立于历史清理。配置使用版本校验，其他人保存后须重新加载。

预览版没有远端 Issue 创建、修改、关闭接口，也不把未对账的草稿判定为“待创建”。正式同步前还需审阅字段映射、远端既有 Issue 对账、冲突和失败重试策略。分组用于汇总，Issue 本身属于具体项目，参见 [GitLab Issues API](https://docs.gitlab.com/api/issues/) 与 [Groups API](https://docs.gitlab.com/api/groups/)。

GitLab 配置页提供“重新设置 API Token”。凭据在该页面重新录入并保存，不在聊天中提供。项目拉取改用 POST 请求体传递凭据；复用已保存凭据时必须保持同一个 GitLab 服务地址。SSH Key 用于 Git 传输，不能替代 Issue API 的 Token。预览阶段不要求授予 Issue 写权限。

当前只允许拥有对应配置权限的全局超级管理员查看和修改映射。页面显示的项目、分组和仓库来自当前系统配置；若缺少带命名空间的仓库路径，请在 GitLab 配置中重新拉取并核对。
