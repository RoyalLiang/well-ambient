# 需求、缺陷与开发追踪分层模型

## 结论

当前团队用 Jira `Task` 记录需求和待开发功能，所以系统应该把 Jira Task 视为需求主线，而不是执行任务。Bug 保持独立缺陷流。AI 解构和代码证据产生的子任务进入执行追踪，用来解释需求或缺陷的开发结果。

这套分层让系统同时支持三类周期：

- 需求开发周期：从录入、澄清、排期、开发、评审到交付。
- 迭代周期：把需求和高优先级 Bug 放进 sprint、版本或交付窗口。
- 追踪周期：持续观察分支、commit、MR、Jira 状态、延期和状态不一致。

## 工作项分层

### 需求主线

需求是可排期、可承诺、可验收的主工作项。

来源包括：

- Jira `Task`、`Story`、`Feature`、`Epic`、`Requirement`。
- 系统内手工录入的口头需求。
- 后续从会议纪要或文档识别出来的需求。

当前落地口径：

- 存储为 `task_telemetries.issue_type = demand`。
- 进入需求看板和排期表。
- 通过 `task_group_id` 绑定 AI 解构出的影子开发任务。
- 风险判断以截止日、分支、更新时间、影子任务进度为主。

### 缺陷流

Bug 不和需求混为一类，但它和需求一样属于可排期、可承诺、可验收的交付项。它可以占用发布版本容量，也可以进入紧急修复；真正执行修复、测试和回归的步骤必须拆成执行任务。

来源包括：

- Jira `Bug`、`Defect`、`缺陷`、`故障`。
- 线上问题、回放问题、测试问题。

当前落地口径：

- 存储为 `task_telemetries.issue_type = bug`。
- 进入交付计划、版本承诺和缺陷治理视角。
- 分别记录受影响版本与目标修复版本；受影响版本不能代替目标修复版本。
- 实际修复步骤作为带显式父交付项的执行任务进入执行追踪，Bug 主卡不在执行列表重复编辑。
- 后续可增加严重级别、影响范围、修复 SLA、复现状态、回归状态。
- 当某个 Bug 阻塞需求交付时，以结构化关系或事件表达依赖，不把 Bug 降级成需求的执行子任务。

### 执行任务

执行任务不是需求池里的主承诺对象，而是解释交付过程的证据单元。

来源包括：

- AI 需求解构生成的影子任务。
- 人工拆分的开发子任务。
- GitLab 分支、commit、MR 反向识别出的开发活动。

当前落地口径：

- 存储为 `task_telemetries.issue_type = task`。
- 进入执行追踪视图。
- 通过 `task_group_id` 回流到需求或缺陷。
- 风险判断以是否有分支、commit、MR、合并状态、最近活动为主。

## 生命周期设计

### 需求开发周期

1. 收集：Jira Task 同步或系统手工录入。
2. 澄清：补充描述、验收标准、负责人、所属项目。
3. 排期：绑定迭代、截止日、负责人、开发分支、任务组。
4. 拆解：AI 或人工生成影子开发任务。
5. 开发：GitLab 分支、commit、MR 产生证据。
6. 验收：需求状态进入评审、测试、验收。
7. 交付：需求完成，归档实际工时、延期原因和上下文事实。

### 迭代周期

迭代不是另一套任务，而是需求和 Bug 的时间盒。

MVP 可以先用排期表承载迭代视角：

- 按截止日、负责人、部门、项目筛选。
- 用 `risk_level` 看逾期、临期、排期缺口和推进停滞。
- 用 `estimate_hours` 汇总容量。
- 用 `task_group_id` 反查执行任务进度。

下一阶段可以新增 `iteration_id` 或 `release_id`：

- 需求和 Bug 都可以进入迭代。
- 执行任务只随父级工作项被带入，不直接占据迭代承诺列表。
- 迭代看板展示承诺、进行中、风险、已交付、延期原因。

本仓库后续以 `ReleaseVersion` 和 `WorkItemReleaseLink` 表达发布承诺；`iteration_id` 仅保留为未来 Sprint/时间盒扩展设想，不作为当前版本事实。

### 追踪周期

追踪周期是自动运行的事实循环：

1. Jira 同步需求和 Bug 状态。
2. GitLab 同步分支、commit、MR 和合并结果。
3. 系统按需求、Bug、执行任务分别计算风险。
4. 高风险事件进入通知中心。
5. 人工干预记录负责人、截止日、状态和原因。
6. 交付后把实际周期、延期原因、验收问题反哺 AI 上下文事实。

## MVP 已落地调整

- 新增需求表单支持所属项目/仓库选择。
- 负责人候选从用户表、Jira 配置、Jira JQL、历史任务、当前登录人聚合。
- Jira `Task` 同步为 `demand`，会进入需求看板和排期表。
- Jira `Bug/Defect/缺陷/故障` 同步为 `bug`，保留缺陷流。
- AI 解构导入的子任务仍为 `task`，进入执行追踪。

## 后续落地建议

- 增加可配置的 Jira 类型映射：让管理员定义哪些 Jira 类型进入需求、缺陷或执行任务。
- 给 Bug 增加缺陷字段：严重级别、复现状态、影响范围、SLA、回归结论。
- 增加迭代表：`iteration_id`、目标、时间窗口、容量、参与人、状态。
- 在排期表中增加“缺陷容量占用”和“执行异常数”。
- 在交付归档中记录实际周期、延期原因和需求变更次数，用于后续估算校准。
