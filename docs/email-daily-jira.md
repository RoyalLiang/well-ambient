# 邮件服务与每日 Jira 早报

在配置中心的“集成设置 → 邮件服务”中使用三个标签页：

- **发信服务**：配置 SMTP 主机、端口、TLS、发件人和认证凭证。保存后显式启用；“发送测试邮件”使用当前草稿和独立测试收件人，不会自动保存。显示“SMTP 已接受”后，请在收件箱/垃圾邮件中确认实际到达。
- **Jira 早报**：配置收件人、发送时间和 IANA 时区（默认 Asia/Shanghai），按需启用每日发送和 commit 统计。默认不开启任何外发。
- **邮件模板**：内置完整中文主题、开场和结尾，无需先调用 AI 即可使用。可点“恢复默认模板”查看候选，显式应用到草稿后保存；这不会直接覆盖现有手工稿。也可输入自然语言需求，让现有 AI 引擎生成一条完整自定义邮件版式（HTML）候选。支持 `{{date}}`、`{{timezone}}`、`{{introduction}}`、`{{closing}}`，以及 `{{yesterday}}`、`{{unresolved}}`、`{{owners}}`、`{{commits}}`、`{{charts}}`、`{{overview_cards}}`、`{{analysis}}`、`{{warnings}}` 等报告区块占位符；服务端先清洗为邮件安全子集，再注入真实数据，不执行脚本。

SMTP 的“握手类型”有显式互斥选项：**STARTTLS · 升级握手**（常用 587）、**SSL/TLS · 隐式握手**（常用 465），以及仅限本机、无认证的明文测试（常用 25）。SSL/TLS 是常见服务商称谓，实际要求 TLS 1.2 或更高。切换模式时仅自动调整原模式的常用端口，自定义端口会保留。

邮件默认包含 **Jira 图表分析**：昨日更新事项的当前状态分布、近 3 天未解决事项的负责人分布，以及开启 commit 后的作者分布图。水平条形图由普通 HTML 表格与内联样式生成，没有 JavaScript、canvas 或外部图片依赖，保留标签、数量、占比和纯文本替代。超过 8 个分类时合并“其他”，无数据时展示说明；这些图表不是历史状态快照，也不用提交数评价个人绩效。未引入 HyperFrames 运行依赖。

早报和模板共享一份草稿，任一“保存早报设置 / 保存模板”都会保存这份完整配置。切换三个标签不会丢失未保存内容。预览使用当前草稿及本地真实数据，正式发送只使用已保存配置；生成或预览不会自动发送。

“项目与负责人分组”按列表顺序匹配，可从 Jira 项目/负责人候选中多选，也可直接输入自定义 Key、项目关键字或姓名；逗号分隔输入会拆为多个值，点击保存时尚在输入框中的值也会先提交。保存成功以服务端 `/api/config` 回读的 `project_groups` 与请求一致为准，刷新和服务重启后保持名称、项目、负责人及顺序；回读不一致时明确报错，不显示乐观成功。每组必须有名称，并至少包含一个项目或负责人。

## 可视化模板图库

邮件模板页上方横向展示截图式缩略预览，下方是同级双面板：左侧编辑已应用草稿，右侧查看完整样式或真实数据预览。缩略图和完整预览均由实际邮件渲染器生成，不是装饰图片。

| 内置样式 | style 值 | 实际邮件结构 |
| --- | --- | --- |
| 晨间简报 / 标准简报 | `brief` | 概览、图表在前，再展开事项与负责人 |
| 行动聚焦 / 重点跟进 | `focus` | 待办数量与未解决事项优先，再看负责人及其他统计 |
| 明细台账 / 紧凑清单 | `ledger` | 紧凑标题与范围明细表优先，再展开图表分析 |
| 全景看板 | `hyperframe` | 汇总指标、分类卡片及图表优先 |

四种内置样式保留相同数据口径，预览与实际发送共用安全渲染路径。旧配置没有 style 时兼容为 brief。

- **查看**：仅切换右侧完整样式。图库使用固定示例数据，清晰标注，不查询真实事项，也不改变草稿。
- **使用模板**：复制文案和 style 到草稿，可通过“撤销应用”恢复。点击“保存模板”后才影响实际发送。
- **生成候选**：Agent 根据需求生成一封完整自定义邮件版式（`style="custom"`），包含主题、开场、结尾和整封 HTML；必须包含 `{{yesterday}}` 与 `{{unresolved}}`，并可组合 `{{charts}}`、`{{overview_cards}}`、`{{analysis}}`、`{{owners}}`、`{{commits}}`、`{{warnings}}` 等报告区块占位符，服务端会清洗为邮件安全子集并注入真实数据，不执行脚本。生成不会覆盖手工编辑。
- **删除**：生成候选支持确认后删除，失败时保留条目并允许重试。内置模板不可删除。删除已使用的候选不改变草稿或已保存的发信配置。
- **持久化**：候选存放在服务端，刷新页面或服务重启后仍可用。自建候选最多 30 条，每次生成保存 1 条；接口仍支持一次保存 1–3 条，超限整批拒绝。

样式示例模式隐藏正式发送操作；返回草稿预览后才能执行已保存配置的发送。真实数据预览返回较慢时，不会抢走用户随后选择的样式。

## 明暗模式

邮件同时声明 light/dark 支持。支持媒体查询的客户端可切换背景、卡片、文字、边框、统计数字及 SVG 图例；同时提供 `[data-ogsc]` / `[data-ogsb]` 暗色标记规则。浅色内联样式保留为回退。窄屏将统计卡片展开，单个状态胶囊保持不折行，不以裁剪隐藏数值。

浏览器预览仍经过 DOMPurify、CSP 和空权限 sandbox。已验证四种模板的明暗浏览器渲染及暗色标记模拟；这不等同于实际 Gmail、Outlook、飞书邮箱等客户端的收信验证。客户端可能过滤 CSS 或 SVG。

已移除“本地没有匹配的昨日 commit 采集记录…”提示，零提交保留采集统计；同步或人员配置的其他真实提示仍保留。无更新事项的解决率显示“—”，不再显示 100%。七日曲线只使用查询到的计数，缺少可用数据范围时显示空态。

## 统计口径

报告日期是发送日 D，时间边界取所选时区的自然日，支持夏令时：

| 内容 | 范围 |
| --- | --- |
| 昨日 Jira | `source_updated_at` 在 `[D-1 00:00, D 00:00)`，包含当前已解决事项 |
| 近7日更新分布 | 按本地记录的最后更新时间 `source_updated_at` 在 `[D-7 00:00, D 00:00)` 分日计数，沿用相同核心成员范围；不是每天所有 Jira 变更事件的次数 |
| 近 3 天未解决 | 创建时间在 `[D-3 00:00, D 00:00)`，当前状态未解决 |
| Coremember | 复用 Jira `sync_users`，为空时尝试解析现有自定义 JQL 的 assignee；未配置时显示警告，不放宽为全量人员 |
| 可选 commit | 本地 `GitCommitLog.created_at` 在昨日范围，仅统计核心成员的 `git_push`，按仓库与 commit SHA 去重，排除已标记重复记录 |

Jira 来自已有本地同步事实，生成早报不会触发额外外部同步。commit 当前模型只保存采集时间，**采集日可能不同于原始提交日**。邮件明确标注此限制；统计分析为确定性事实说明，不用提交数推断生产力或代码质量。没有匹配 commit 记录时不再额外显示同步或身份映射警告；零条仅指本地采集结果。

## 调度与运行要求

服务进程运行时每分钟检查一次；到达所设时间后发送。当天重启可补发当日报告，不回放之前日期的积压报告。使用数据库 `daily_jira_email_runs` 表的日期主键保证每个报告日最多尝试一次，手动和定时发送共用记录。发送记录显示最近 14 次尝试。

SMTP 与数据库之间没有分布式事务。网络中断或服务崩溃可能留下“发送中或结果待确认”“失败或结果未知”；为避免重复邮件，这些日期不会自动重发。该机制是**最多尝试一次**，并非保证投递成功。成功仅表示 SMTP 接受邮件。

升级需要通过项目既有迁移流程创建 `daily_jira_email_runs` 和 `email_template_candidates` 表；当部署关闭自动迁移时，请先执行该部署的数据库迁移再启用邮件功能。本次实现不修改运行中的生产数据库、不启用生产配置、不提供真实凭证。

## 安全与权限

- 邮件操作与运行配置始终使用全局 `config:read` / `config:write` 授权，仓库作用域参数不能提升为全局邮件权限。
- SMTP 密码沿用既有运行配置持久化；读取返回 `__configured__` 标记，版本与差异不包含明文。运行配置数据库本身仍需按现有部署方式保护。
- 默认使用 STARTTLS，TLS 连接验证证书；无加密模式仅允许本机无认证测试接收器。
- 主题与邮箱拒绝换行注入，正文模板自动 HTML 转义；浏览器预览额外净化并放在 sandbox iframe 中。
- SMTP 请求有超时和取消，错误不回显可能包含敏感信息的 SMTP 原始回复。

## API

| 方法与路径 | 用途 |
| --- | --- |
| GET / POST `/api/config` | `smtp` 与 `daily_jira_email` 配置、统一版本管理 |
| POST `/api/config/test` | `{type:"smtp",smtp:{...},recipient:"..."}`，真实发送一封测试邮件 |
| POST `/api/daily-jira-email/template` | `{requirements:"..."}`，返回一条自定义整版模板候选（`style="custom"`，含完整 HTML 版式与文案，必须包含 `{{yesterday}}` 与 `{{unresolved}}`）；本接口不入库，由前端调用 `/templates` 保存 |
| GET `/api/daily-jira-email/templates` | 四种内置模板及已保存候选，含安全示例 `preview_html` |
| POST `/api/daily-jira-email/templates` | `{templates:[{name,template}]}`，原子保存 1–3 条候选，返回新建 DTO |
| DELETE `/api/daily-jira-email/templates/{id}` | 删除自建候选，不影响生效模板 |
| POST `/api/daily-jira-email/preview` | `{date?:"YYYY-MM-DD",settings?:{...}}`，不发送 |
| POST `/api/daily-jira-email/send` | `{date?:"YYYY-MM-DD"}`，只使用已保存配置 |
| GET `/api/daily-jira-email/runs` | 最近 14 次发送尝试 |

## 邮件与文档独立投递（2026-09）

Confluence 同步失败不再阻止早报发信。运行记录分别保存邮件状态、文档同步状态和本次收件人；已发送邮件对应的“重试同步”只重试 Confluence，不再次调用 SMTP。并发点击使用数据库条件更新保证只有一次同步。当天已经发送后，修改发送时间、再次定时触发或手动发送均不会重发。历史 `confluence_failed` 表示此前未进入 SMTP，可安全重试完整发送流程；未知 SMTP 结果仍不得自动重试。

邮件 `To` 头使用本次实际收件人，发送记录也展示收件人快照。历史未保存的收件人显示“历史记录未保存”。升级需迁移运行记录新增的 `recipients_json`、`confluence_status`、`confluence_error` 字段。

启用提交统计时，邮件与 Confluence 顶部展示昨日 Commit / MR 并列柱状图。按报告时区的昨日采集时间统计核心成员：Commit 按仓库和 SHA 去重，MR 按仓库和 IID 去重（打开、更新、合并同一 MR 只计一次）。不将数量用于推断质量或生产力。

## 定位 Confluence 同步失败

同步错误保留失败阶段（读取父页、查找或创建日期页、上传图表附件、更新正文）及 HTTP 状态码，并写入运行记录和服务日志。日志只输出报告日期、是否仅同步、脱敏诊断，不记录令牌、上游响应正文或报告内容。400 表示参数或正文被拒绝，401/403 为认证或权限问题，413 为服务端大小限制，429 为限流，502/503/504 为服务或网关异常；需结合失败阶段定位，不应仅凭“同步失败”推断原因。

无效的 Confluence 配置只阻止文档同步，不阻止生成并发送邮件。父页读取成功只能证明读取权限，不能证明建页、附件上传或正文更新权限。历史运行记录没有保存底层错误时，不能追溯确定根因。

本地只读报告诊断测试：显式设置 `WELL_CONFLUENCE_DIAGNOSTIC_DB` 为数据库绝对路径、`WELL_CONFLUENCE_DIAGNOSTIC_DATES` 为逗号分隔日期，运行 `go test ./internal/server -run '^TestConfluenceLocalReportDiagnostic$' -v`。测试只读取本地数据并验证报告转换和 XML；不调用 SMTP 或 Confluence 写接口。
